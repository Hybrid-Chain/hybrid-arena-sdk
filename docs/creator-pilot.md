# Independent creator pilot

Goal: a developer who did not implement Arena can build a game, connect real
authoritative facts, publish a Testnet release and receive useful player feedback.
Synthetic QA or an operator running privileged scripts does not satisfy this goal.

## Trial record

Record SDK artifact/version, exact release digest, tester role, start/end time,
first useful receipt, setup minutes, support interventions and blocker category.
Keep identities, credentials and native player IDs private. Ask permission before
publishing a tester's name or feedback. Use the Studio report form for observations;
it intentionally marks every submission self-reported/unverified.

## Developer journey

1. Follow the public guide without undocumented operator help. Register a workspace,
   game and exact release; tailor the starter with its manifest.
2. Issue a source key privately, launch loopback, play against the labeled bot and
   deliver an entire ordered match. Then adapt it to a genuinely different game.
3. Lose one successful reply and restart. Recover its original receipt exactly once.
   Try wrong game/key, changed terms and an explicit source gap; verify rejection.
4. Inspect a complete Testnet proof in Explorer and publish the exact release.
   Confirm external game TLS/admission/abuse controls before inviting public players.
5. Exercise a scoped CLI token: read diagnostics and draft a rule; confirm publishing,
   source-key issuance, trading and cross-game reads fail. Revoke it and retest.
6. If implementing source admission, test approval, rejection, expiry, changed
   sequence/quote, lost reply, restart and a simultaneous terminal event.

## Player journey

Find a real published game, understand test units and participation policy, explicitly
join its simulation, buy, partially exit, cancel a remainder and inspect settlement.
Players may watch, predict and join only when the actual game admits them. No game
slot, favorable outcome or payout is promised. Compare final statements and proof.
Share the game, post genuine feedback and exercise one release-bound promotion vote.
Do not generate fake players, trades, traffic, feedback or community support.

## Acceptance and stop conditions

Capture actual pass/issue/not-tested evidence and support needed. A reviewer separate
from the creator must inspect the trial before claiming independent acceptance.
Missing/held evidence, broken consent, duplicate effect, conservation failure, leaked
credential or unclear non-value labeling stops promotion. Self-reports, vote overrides
and Testnet certificates alone cannot unlock Mainnet or money movement.

Success metrics: time to first valid receipt, time to a complete proof, number of
operator interventions, unresolved blockers, player task completion and actionable
feedback. Do not invent numerical adoption or revenue targets from this trial.
